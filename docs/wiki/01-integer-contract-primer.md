# 01 — The integer contract primer (why every integer is frozen)

## Formats in one table

| Tensor | Format | Scale | Notes |
| :---- | :---- | :---- | :---- |
| Weights | INT8, symmetric | per-output-channel | one multiplier+shift per channel |
| Activations | INT8 | per-tensor | zero point = real zero (by design) |
| Accumulators | INT32 | exact | never rounded mid-reduction |
| Gate inputs | Q7.10 INT16 | 2^-10 | round-half-to-even |
| Gate LUT outputs / in-flight hidden | Q1.15 INT16 | 2^-15 | table lookup |
| Committed hidden | Q7.8 INT8 | 2^-7 | `>>8` then round-half-to-even + saturate |

## Why frozen integers matter

A requantized INT8 dataflow has this irreducible idea: multiply the INT32
accumulator by a per-channel fixed-point multiplier, shift right with
**round-half-to-even**, add the zero point, and saturate to int8. Different
tools choose different tie rules; the frozen contract pins them:

- `requantize` lives once, in the oracle, `mgr1::requantize` in C++
  (`hls/common/mgr1_types.h`), and both must agree at the boundary
  witnesses. Run `python3 -c "from integer_oracle import requantize; print(requantize(1000000, 18226, 21, 0))"` — you should see `127`.
- The gate order is the exported PyTorch order (reset, update, new): `r =
  sigmoid(a_r + u_r)`, `z = sigmoid(a_z + u_z)`, `n = tanh(a_n + r * u_n)`,
  `h = (1-z) * n + z * h_prev`. The reset gate multiplies the candidate
  affine result **including its recurrent bias** — `bench/replay.py
  gate_order_witness` proves a perturbation of `b_hh` of the candidate
  section can change the output when `r < 1`.
- Cached replay (`model/integer_oracle/replay.py`) must equal dense replay
  on every hidden state; `tests/test_replay.py` holds that line.

## The regeneration discipline

Generated artifacts (CSR defs, activation LUT ROM header, golden vectors,
docs/03 + docs/06) are never hand-edited — regenerate with the tools in
`tools/` and commit the regenerated bytes. `tests/test_lut_header.py` +
`tests/test_csr.py` re-verify idempotence and boundary witnesses on every
run. If an oracle change is required: change the oracle FIRST, then
regenerate vectors + docs, and only then touch kernels.
